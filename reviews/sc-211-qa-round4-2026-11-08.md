- **B5 source half — fixed.** A listing whose only Tier-1 claim is re-pointed ends
  `UNVERIFIED`, hand-cut `NULL`, basis `NULL`, cross `UNCERTAIN`, 0 claims and
  no `listing_search` row (P1). With another Tier-1 claim left, the source stays
  `VERIFIED` with basis `CERTIFIER_REGISTRY` and hand-cut **FALSE** when that
  remaining claim declares `NOT_HAND_CUT` — proof it is re-derived, not frozen
  (P3).
- **B5 destination half — NOT fixed.** `reattachClaim` recomputes only
  `fromListingId`; `applyBatch` recomputes only write targets. With
  `applyBatch(writes = emptyList(), reattachments = …)` the destination holds 2
  claims (one Tier-1) but stays `UNVERIFIED`, hand-cut `NULL`, basis `NULL`,
  cross `UNCERTAIN`, and **0** index rows (P2a/P2b/P2c). Through
  `LoadIngestionBatch` the same decision is correct (P7) because the planner
  always writes `Update(base)` for the destination. The invariant therefore
  holds in production only by planner accident; the repository port allows the
  stale state and the project's own attach-to test uses the reattachment-only
  shape.
- **B6 — fixed.** On a Tier-3 row: curated `UNCERTAIN` → 0 index rows,
  `NO_CROSS_CONTAMINATION` → 1, `PRESENT` → 0, DB value matching each step
  (P4). A Tier-1 claim still forces `NO_CROSS` over a curated `PRESENT` on both
  insert and update (P5).
- **Gap nits — fixed.** An ungeocodable row is exactly one `NO_GEOCODER_MATCH`
  reject with no "outside every configured metro" gap (M1; two such rows → 2
  rejects, M6). A row in a configured but unselected metro is reported as
  `hms: 1 row(s) in a configured metro that was not selected` and counted
  nowhere else (M2, M5). Coordinate rows outside every circle stay gaps with no
  reject and no geocoder call; located-but-outside rows stay gaps (M3, M4).
